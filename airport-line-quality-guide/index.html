01

为什么不能迷信客户端列表里的「绿色延迟数字」？

几乎每个新手都踩过这个坑：点一下客户端「全部测速」，某节点后面显示绿油油的 28 ms，一点过去看 YouTube 却连首页缩略图都刷不出来。

原因很简单：客户端的 UrlTest 仅仅测了一次小 HTTP 204 握手包耗时（还可能只测到了国内转发入口机），既测不出连续丢包抖动，也测不出单线程大文件吞吐上限与目标出口解锁能力。

02

四步闭环实战法：2 分钟自己验出线路真伪

Step 1 · 卡定晚高峰 20:30–22:30 开测

黄金试金窗

白天上午公网都挺快，毫无参考价值！务必在晚高峰打开常用视频平台（4K 自动码率），点开右上角 Stats for nerds（详细统计） 看实时连接速率与 Buffer 缓冲健康条。

Step 2 · 配合站内工具查 IP 属地与解锁

工具直达

节点连上后，结合站内 IP 归属地查询 与 多节点连通性测试 检查出口是不是纯正原生地域、有无被大量污染降权。

Step 3 · 测流式 AI 与 DNS 防泄漏

防 403 核验

对 ChatGPT / Claude 提一段超长代码输出需求，观察吐字是否连续不中断、用 DNS 检测工具 验证无国内运营商解析泄漏。

Step 4 · 单线程真实下载观察降速曲线

防限速验真

尝试从 GitHub Releases 下载一个 300–500MB 的开源安装包，观察前 3 秒过后后半程速度是否稳定坚挺，还是瞬间被机场 QoS 限速腰斩。

04

高频疑问解答（FAQ）

用手机端 Fast.com 或 Speedtest 测速靠谱吗？

相对客观（能跑真实多线程 HTTP/TCP 传输并显式输出缓冲延迟 Bufferbloat），但要注意：1 次全速测速会白白消耗掉约 300MB–1.5GB 套餐流量，不要对着同一个节点反复连测几十次，还需结合本地晚高峰体感为准。

同宽带下为什么邻居用某机场飞快，我连同一个订阅却总卡？

先排查是不是你自己电脑端/路由器问题：是否混用了其他翻墙浏览器插件、路由器是否开启「双拨」或「QoS 限速」、系统是否装有特定安全杀毒软件拦截了 TLS 包。
